# House tone: understated NeurIPS / ICML

Default voice for all `rx-write` drafts unless the project style guide
explicitly overrides a narrower venue rule. Prefer calm precision over sales.

## Voice

1. **Quiet confidence.** State what you did and what the gated evidence shows.
   Do not advertise importance; let the problem and numbers do that work.
2. **Claim only what `can_promote` allows.** Stronger wording requires stronger
   evidence. Speculative ideas stay hedged or marked `[UNSUPPORTED]`.
3. **Specific over glowing.** Prefer mechanisms, metrics, and deltas to
   adjectives.
4. **Fair to prior work.** Describe neighbors accurately; contrast on mechanism
   or assumption, not by belittling them.
5. **Short sentences, one idea each.** Formal but readable — not theatrical.

## Ban / replace list

| Avoid (hype / vague) | Prefer |
|----------------------|--------|
| novel / groundbreaking / state-of-the-art* | name the concrete delta (*“SOTA” only with a cited, gated comparison) |
| powerful / robust / seamless / elegant | say what property improved and by how much |
| remarkable / significant gains† | report the number (†“significant” only for statistical tests) |
| comprehensively / extensively | state the actual suite (N datasets, K seeds, listed ablations) |
| clearly shows / proves‡ | “we find”, “results indicate”, “Table 1 shows” (‡reserve “prove” for proofs) |
| paves the way / opens the door | one concrete implication or future experiment |
| In recent years… / LLMs have revolutionized… | start with the specific problem or result |

## AI-tell hygiene

Beyond hype words, a draft can still read as machine-generated through structural tics a
human editor would catch: stock clichés, transition-word overuse, and unnaturally uniform
sentence rhythm. `rx_state.aitells.scan_ai_tells(text)` catches the first two:

- **Hard-banned clichés** (zero tolerance, rewrite on any hit): "delve into", "boasts",
  "rich tapestry", "testament to", "navigate the complexities", "unlock the potential",
  "harness the power", "game-changer", "cutting-edge", "ever-evolving landscape",
  "fast-paced world", "plays a crucial/pivotal role".
- **Overused transitions** (legitimate in small doses, flagged past
  `transition_threshold=3` uses in one paper): "moreover", "furthermore", "additionally",
  "in conclusion", "in summary", "it is important/worth noting", "notably". Vary
  connective language instead of reaching for the same transition every paragraph.
- **Sentence rhythm.** `rx_state.aitells.low_burstiness(text)` flags a section where every
  sentence is roughly the same length — a real writer's sentence length varies; a flat
  rhythm is a generation tell. Mix short declarative sentences with longer ones (see
  `writing-craft.md`'s paragraph architecture) rather than defaulting to uniform
  ~20-word sentences throughout.

## Hedging policy

- **Do hedge** when the claim is out of scope, under-powered, or not gated.
- **Do not hedge** gated main results with decorative “may/might/could potentially”.
- Pattern: unqualified claim ↔ supported/strong evidence; scoped claim ↔ limitation.

Examples:

- Bad: “Our method may potentially achieve remarkable improvements.”
- Good: “On Dataset D, method M improves metric M↑ by 2.1 over baseline B (Table 1; 3 seeds).”
- Bad: “We prove that transformers are obsolete.”
- Good: “Under the locked protocol, M matches B on the primary metric and reduces latency by 18%.”

## No internal identifiers in reader-facing text

`.rx/experiments/EXP<n>/`, run/job IDs, `.rx/` paths, and generated-artifact filenames
(`reviewer_system_eval.json`, etc.) are project bookkeeping. A reader has no `.rx/` directory
and cannot resolve `EXP19` to anything. Every such reference in `main.tex` prose or a table/
figure caption is a bug, not a style choice — it reads as an internal draft that was never
cleaned up.

- **Do**: name the analysis in plain language and point to the table/section/figure that
  carries it — "a paired-bootstrap analysis (Table 3)" not "EXP15 (Table 3)"; "the same prompt
  run across all 12 held-out papers" not "EXP19 confirms...".
- **Do** use `\label`/`\ref` for cross-references within the paper (`Section~\ref{sec:...}`,
  `Table~\ref{tab:...}`), never a hardcoded section number and never an internal ID as the
  anchor.
- **Don't** hand-edit a `*_tables.tex` (or any `% Generated by ...` file) to add a sentence
  referencing a new run. Edit the generating script so the caption is produced correctly next
  time too, then regenerate. A hand-edit that bypasses the generator is exactly how a stale
  hardcoded section reference (e.g. a caption still pointing at "Section 3.4" after the section
  moved to 3.2) survives into a submission — the generator doesn't know the hand-edit exists
  and won't reproduce or catch it on the next run.
- Before finalizing any draft or revision, grep the rendered `main.tex` and every `\input`ed
  `.tex` file for `EXP[0-9]`, `RUN[0-9]`, and `\.rx/` (or the project's equivalent tracking
  prefix). Any hit in prose or a caption must be rewritten before the paper is considered done —
  treat this with the same seriousness as the anonymity lint in `SKILL.md`.

## Section tone notes

| Section | Tone cue |
|---------|----------|
| Abstract | Dense and factual; headline number; no hype opener |
| Introduction | Motivation via the gap, not via field success stories |
| Method | Neutral engineering prose; motivation without drama |
| Experiments | Report-first; takeaway sentence, then numbers |
| Related Work | Map + precise contrast; no dunking on prior work |
| Limitations | Direct and scoped; not apologetic theater |
| Conclusion | Restate ping + gated finding; concrete future work |

## Relationship to style calibration

If `.rx/notes/style-guide.md` exists, inherit its **structure** and local
wording habits, but **this house tone wins** on hype words, hedging, and
claim strength. If the style guide itself is salesy, do not copy that voice.

## Quick self-check before finishing a draft

- [ ] No banned hype words unless replaced by a gated specific claim
- [ ] Every assertive result sentence points to a table/figure or theorem
- [ ] Prior work is described fairly
- [ ] Limitations are plain, not performative
- [ ] A skeptical reviewer would not call the prose “marketing”
- [ ] Zero matches for `EXP[0-9]`, run/job IDs, or `.rx/`-style internal paths anywhere in
      `main.tex` or its `\input`ed files (grep it; don't eyeball it)
- [ ] Abstract carries at most 1-2 headline numbers as plain point estimates — no exact
      confidence intervals or p-value notation stacked sentence after sentence (see
      `abstract.md`)
- [ ] `rx_state.aitells.scan_ai_tells(text)` returns no hard-banned clichés and no
      transition-word overuse; `rx_state.aitells.low_burstiness(text)` is `False` for
      Introduction/Method/Conclusion (see "AI-tell hygiene" above)
