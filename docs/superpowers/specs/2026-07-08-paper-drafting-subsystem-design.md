# Paper drafting subsystem — LaTeX output + iterative drafting loop

**Date:** 2026-07-08
**Status:** Approved (brainstorm) → ready for implementation plan
**Author:** Louis + Claude

## Problem

Two gaps in the paper back-end of the rx pipeline:

1. **Format.** `rx-write` renders the paper outputs (`paper/arxiv/`, `paper/anon/`) as generic
   markdown-style drafts. Publication needs **LaTeX**.
2. **Single-shot drafting.** `rx-write` produces one draft; `rx-review` critiques it and drafts
   rebuttals, but nothing applies the findings back to the paper. There is no iterative
   improvement — the human does it by hand.

The system already has one self-improving loop (the **research loop**: hypothesis → question →
experiment → results → revisit, via `rx_state.pipeline.loop_step`). It should have a second: a
**drafting loop** that iterates `draft → review → fix → review → …` until the review is clean.

## Solution

Overhaul the paper drafting subsystem across `rx-write`, `rx-review`, and `rx-pipeline`, plus
three new/extended `rx_state` helpers. These changes are coupled (the loop's fix step edits the
LaTeX), so they share one spec; the implementation plan decomposes them into small TDD tasks.

After this change the system has **two loops**:
- **Outer research loop** — `loop_step`, ideate ↔ experiment, driven by evidence (unchanged).
- **Inner drafting loop** — `draft_loop_step`, write ↔ review, driven by review findings (new).
  Runs at the `write`/`review` stage, after the research loop has settled.

## Component 1 — LaTeX output (`rx-write`)

Each paper directory renders as LaTeX **source only** (no PDF compilation — no toolchain
dependency added to the pipeline):

```
paper/arxiv/{main.tex, preamble.tex, refs.bib}   # full identity
paper/anon/{main.tex, preamble.tex, refs.bib}    # double-blind, anonymized
code/ + code/REPRODUCE.md                         # unchanged
blog/<slug>.md                                    # unchanged — stays markdown
```

- **`preamble.tex`** — a static shared preamble (`\documentclass`, common packages, `\newcommand`
  helpers) shipped as the constant `rx_state.latex.PREAMBLE`. Both `arxiv/` and `anon/` write the
  same preamble file.
- **`refs.bib`** — generated by the new helper `rx_state.latex.render_bib(notes)` from the survey
  PaperNotes at `.rx/notes/papers/*`. Each note yields one bibtex entry keyed by `note.key` with
  the fields available on a `PaperNote` (`title`; `note` on method/claim as needed). Unknown fields
  (author, year, venue) are emitted as **empty** bibtex fields (`author = {},`) for the human to
  enrich — this is defined behavior, not a placeholder.
- **`main.tex`** — the paper body, LLM-authored from claims/evidence exactly as today (prose-driven
  in the SKILL, not a Python renderer), now in LaTeX. Evidence gating is unchanged: any claim where
  `rx_state.gates.can_promote` is False is rendered `[UNSUPPORTED]`, never stated as fact.
- **Anonymity unchanged in mechanism.** `rx_state.anonymize.anonymize_text` produces `anon/main.tex`
  from the source; `rx_state.anonymize.lint_anonymity` runs on the `anon/` `.tex` text until clean.
  Both are regex-based on names/URLs and operate on LaTeX source without modification.

## Component 2 — Persisted review findings (`rx-review`)

For the loop to hand findings from review to the revise step across separate skill invocations,
findings must live on disk (today they exist only in-session).

- `rx-review` writes each round's `ReviewFinding`s to `.rx/reviews/round-<n>.md` via a new helper
  `rx_state.review.write_round(rx_dir, n, findings) -> str` (returns the path).
- Companion helpers `rx_state.review.read_round(path) -> list[ReviewFinding]` and
  `rx_state.review.latest_round(rx_dir) -> int` (highest existing round number, or 0 if none).
- The round file records each finding's `reviewer`, `severity`, and `comment`, plus the panel
  `recommend(findings)` result, so `draft_loop_step` and the revise step can read both.

## Component 3 — Revise mode (`rx-write --mode=revise`)

`rx-write` gains an explicit mode selector:

- **`--mode=draft`** (default) — initial draft from evidence. Current behavior, now emitting LaTeX
  per Component 1.
- **`--mode=revise`** — reads the latest round via `rx_state.review.latest_round` /
  `read_round`, edits the existing `paper/arxiv/main.tex` (and re-renders `anon/`) to address each
  finding, preserving evidence gating and re-running the anonymity lint. Does **not** regenerate
  `preamble.tex`/`refs.bib` unless a finding requires it.

## Component 4 — Drafting loop (`rx-pipeline`)

A new inner loop parallel to the research loop, driven by a new pure helper mirroring `loop_step`:

```python
def draft_loop_step(draft_loop: dict, recommendation: str) -> tuple[dict, str]:
    # increments draft_loop["iteration"]
    # "stop_clean"  if recommendation in {"accept", "minor revision"}
    # "stop_budget" if iteration >= draft_loop["max_draft_iters"]
    # "continue"    otherwise
```

- Loop state lives under `state["draft_loop"]` (`iteration`, `max_draft_iters`), added to
  `rx_state.store.default_state` alongside the existing `loop` block.
- Orchestration in `rx-pipeline`:
  1. `rx-write --mode=draft`
  2. `rx-review` → writes `.rx/reviews/round-<n>.md`, yields `recommendation`
  3. `draft_loop_step(draft_loop, recommendation)`:
     - `stop_clean` → recommendation is `accept` or `minor revision` → finish
     - `stop_budget` → iteration budget hit → finish, **reporting residual major findings honestly**
     - `continue` → `rx-write --mode=revise` → back to step 2
- The drafting loop runs at the `write`/`review` stage, i.e. after the research loop settles. It is
  independent of `--loop` (the research loop flag); the drafting loop always runs when the pipeline
  reaches `write`.

## New / changed `rx_state` API (all unit-tested)

- **`rx_state.latex`** (new module):
  - `PREAMBLE: str` — static shared LaTeX preamble.
  - `render_bib(notes: list[PaperNote]) -> str` — bibtex from PaperNotes, empty fields for unknowns.
- **`rx_state.pipeline.draft_loop_step(draft_loop, recommendation) -> tuple[dict, str]`** — as above.
- **`rx_state.review`** additions:
  - `write_round(rx_dir, n, findings) -> str`
  - `read_round(path) -> list[ReviewFinding]`
  - `latest_round(rx_dir) -> int`
- **`rx_state.store.default_state`** — gains a `draft_loop` block (`iteration=0`,
  `max_draft_iters` default, e.g. 5).

## Prose / SKILL updates

- `rx-write/SKILL.md` — LaTeX outputs (Component 1) + the `draft`/`revise` mode section (Component 3).
- `rx-review/SKILL.md` — persist rounds via `write_round` (Component 2).
- `rx-pipeline/SKILL.md` — drafting-loop orchestration + `draft_loop_step` (Component 4).
- `AGENTS.md` — the "Outputs of a run" section updated to LaTeX; a two-loop description (research
  loop + drafting loop).

## Failure modes & mitigations

- **No PaperNotes** → `render_bib([])` returns an empty-but-valid `.bib` (no crash); `main.tex`
  simply cites nothing.
- **Drafting loop never converges** → bounded by `max_draft_iters`; on `stop_budget` the pipeline
  finishes and reports the residual major findings rather than looping forever.
- **`--mode=revise` with no prior round** (`latest_round == 0`) → error clearly, instruct to run
  `--mode=draft` first; do not silently no-op.
- **Anonymity leak after a revise** → the revise path re-runs `lint_anonymity` on `anon/main.tex`
  and must be clean before the round is considered done, same gate as the initial draft.

## Non-goals (YAGNI)

- No PDF compilation / `latexmk` / Makefile — `.tex` source only.
- No bibliography enrichment beyond what a `PaperNote` carries (author/year left empty for the
  human).
- No change to the research loop, evidence gates, or the blog output.
- The drafting loop does not re-run experiments or touch `.rx/` evidence — it only edits the paper.

## Testing

- `rx_state.latex`: `render_bib` emits one entry per note, empty fields for unknowns, valid bibtex
  for the empty-list case; `PREAMBLE` contains `\documentclass`.
- `rx_state.pipeline.draft_loop_step`: `stop_clean` for `accept` and for `minor revision`;
  `continue` for `reject` until budget; `stop_budget` at the limit; iteration increments each call.
- `rx_state.review` round I/O: `write_round` then `read_round` round-trips findings and severities;
  `latest_round` returns the highest round number and 0 when none.
- `rx_state.store.default_state`: includes a `draft_loop` block with the documented keys.
- SKILL frontmatter/content tests: `rx-write` body mentions LaTeX + both modes; `rx-review` body
  mentions `write_round`/rounds; `rx-pipeline` body mentions `draft_loop_step` + the two loops.
- Behavioral spine: an end-to-end test that a `reject`→`accept` sequence drives exactly one revise
  cycle and stops `clean`, and that a persistent `reject` stops at `max_draft_iters`.
